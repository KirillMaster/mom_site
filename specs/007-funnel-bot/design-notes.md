# Spec 007: Минимальная воронка в Telegram-боте @angela_moiseenko_bot

**Status**: Draft
**Created**: 2026-10-02
**Боты**: `@angela_moiseenko_bot` — публичный, общается с клиентом (`FUNNEL_BOT_TOKEN`); `mom_site_bot` — приватный, присылает лиды админам (`TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_IDS`, уже работает)

## Что уже есть (переиспользуем, не дублируем)
| Есть | Где | Как используем |
|---|---|---|
| Лиды `ContactMessage` + `/admin/messages` + счётчик непрочитанных | Core/Models, AdminController | Лид из бота сохраняется как `ContactMessage` и появляется в админке |
| `IFeedbackNotifier` → `TelegramNotifier` (mom_site_bot, все `TELEGRAM_CHAT_IDS`, таймаут 10 с, ошибки не роняют запрос) | Infrastructure/Notifications | Отправка лида маме — **тот же вызов** `NotifyAsync(ContactMessage)` |
| Email-уведомление о заявке | EmailNotifier | Срабатывает автоматически, через тот же список notifier'ов |
| `LeadSource.Describe` (UTM → «Источник: …») | LeadSource.cs | `UtmSource=telegram_bot`, `UtmCampaign=<payload>` |
| `extra_hosts api.telegram.org` | docker-compose.prod.yml | Исходящие запросы бота идут тем же путём |

Новое — только клиент публичного бота (приём апдейтов и сценарий диалога).

## Точки входа (deep-link)
`https://t.me/angela_moiseenko_bot?start=<payload>`, payload ≤ 64 символов, `[A-Za-z0-9_-]`:
| payload | Откуда | Поведение |
|---|---|---|
| `art_<id>` | кнопка «Узнать цену / Написать в Telegram» на карточке работы | приветствие с фото и названием работы, цель = «Купить эту работу», шаги 2–3 пропускаются |
| `mk` | лендинг или пост о мастер-классах | цель = «Мастер-класс» |
| `interior` | страница для дизайнеров | цель = «Картина для интерьера» |
| `<любой>` / пусто | реклама, соцсети | полный сценарий; payload записывается в `UtmCampaign` |

Сайт: ссылки с целью Метрики `telegram_click` (`lib/analytics.ts`); сам deep-link CTA — отдельная задача E.

## Сценарий (кнопки inline, свободный ввод там, где указано)
1. **Цель**: Купить картину · Картина для интерьера · Заказать картину · Мастер-класс · Другой вопрос
2. **Уточнение** (в зависимости от цели):
   - интерьер или заказ: размер (до 50 см · 50–100 · больше 100 · не знаю), затем тема или стиль (свободный текст, можно пропустить);
   - мастер-класс: формат (для себя · вдвоём · группа или корпоратив · подарочный сертификат);
   - «Другой вопрос»: свободный текст, затем шаг 4.
3. **Бюджет** (кроме мастер-класса): до 30 тыс. · 30–70 тыс. · 70–150 тыс. · больше 150 тыс. · пока не знаю
4. **Контакт**: кнопка «📱 Поделиться номером» (`request_contact`) или «Пишите мне в Telegram». Если у пользователя нет `@username`, просим номер.
5. **Имя**: подставляем `first_name` с кнопкой «Да, это я» или принимаем свободный ввод.
6. **Готово**: «Спасибо! Анжела ответит вам лично в течение дня» и ссылки на галерею и отзывы. Лид отправлен.

Дополнительно:
- Команды: `/start`, `/cancel` (сброс сценария).
- Текст вне сценария сохраняется как лид «Другой вопрос» с этим текстом.
- Кнопка «Назад» на шагах 2–5.
- Перед шагом 4 показываем строку о согласии на обработку данных (152-ФЗ) со ссылкой на `/privacy`. Такой страницы нет — **входит в эту фичу** (см. ниже).

## Лид → мама
```
ContactMessage {
  Name     = имя,
  Email    = "",                        // см. решение D2
  Phone    = номер | null,              // новое поле
  TelegramUsername = @username | null,  // новое поле
  TelegramUserId   = long,              // новое поле, нужно для ссылки «написать»
  Subject  = "Telegram-бот: <цель>",
  Message  = "Размер: …\nТема: …\nБюджет: …\nРабота: <название> <ссылка>",
  UtmSource = "telegram_bot", UtmCampaign = payload
}
```
- Сохранение в БД, затем `foreach notifier → NotifyAsync(message)`, как в `PublicController.ContactMessage`. Общий код выносим в сервис `LeadService.SubmitAsync`, который вызывают и контроллер, и бот. Так логика не дублируется.
- `TelegramNotifier.BuildText` дополняется строками `Телефон` и `Telegram: @user` или ссылкой `tg://user?id=…`, чтобы мама могла сразу написать клиенту.

## Технические решения
| # | Решение | Почему |
|---|---|---|
| D1 | **Long polling** (`getUpdates`, timeout 50 с) в `BackgroundService` внутри api-контейнера; включается только при заданном `FUNNEL_BOT_TOKEN` | Не нужен публичный webhook-маршрут в nginx и TLS-настройка, нет отдельного контейнера. Исходящий трафик уже работает через `extra_hosts`. Одна реплика api, поэтому конфликта `getUpdates` нет |
| D2 | Миграция: `ContactMessage.Email` становится nullable, добавляются `Phone`, `TelegramUsername`, `TelegramUserId`. Валидация email остаётся в `ContactMessageDto` формы сайта | Не подставлять фиктивный email |
| D3 | Состояние диалога — `IMemoryCache` по `chatId`, TTL 24 ч | MVP: после рестарта контейнера теряется только незаконченный диалог. Таблица в БД — позже, если понадобятся «брошенные» воронки |
| D4 | Клиент Bot API — свой тонкий `TelegramBotClient` на `HttpClient` (`getUpdates`, `sendMessage`, `sendPhoto`, `answerCallbackQuery`), DTO только нужных полей | Без внешних пакетов; `TelegramNotifier` уже ходит в API тем же способом |
| D5 | Только приватные чаты (`chat.type == private`), остальные апдейты игнорируются; в BotFather `/setjoingroups → Disable` | Сейчас `can_join_groups=true` |
| D6 | Лимит: не больше 3 лидов на пользователя в сутки, не больше 1 сообщения в секунду на чат | Защита от спама маме |
| D7 | Логи: `System.Net.Http.HttpClient` → Warning (**уже исправлено** в этой ветке: раньше токен писался в лог в URL) | P4 |

Структура (P3 — файлы не больше 200 строк):
- `Infrastructure/TelegramBot/`: `TelegramBotClient`, `BotUpdateDtos`, `FunnelPollingService`, `FunnelDialog` (конечный автомат, чистые функции `(state, update) → (state, replies, lead?)`), `FunnelTexts`;
- `Core/Services/LeadService`.

## Страница `/privacy` (входит в фичу)
- SSR-страница `frontend/app/privacy/page.tsx`, текст — через существующий `PageContent` (ключ `privacy`), правится в `/admin/pages`; дефолтный шаблон политики ПДн (152-ФЗ): оператор, состав данных (имя, телефон, email, Telegram), цели (обратная связь), срок хранения, отзыв согласия.
- Ссылки: футер, форма контактов (строка согласия под кнопкой), бот (шаг 4), `sitemap.ts`.

## Тесты (P5)
- Unit: конечный автомат `FunnelDialog` (каждая ветка, «Назад», `/cancel`, deep-link `art_<id>` с несуществующим id, текст вне сценария), разбор payload, сборка лида, лимиты.
- Integration: фейковый HTTP-хендлер Bot API, полный диалог, после которого `ContactMessage` есть в БД и вызван `IFeedbackNotifier`; `PublicController.ContactMessage` по-прежнему работает через `LeadService`.
- Ручная проверка: пройти воронку с телефона и получить лид в mom_site_bot и в `/admin/messages`.

## Не делаем в MVP
Ответ маме клиенту через бота (она пишет напрямую), рассылки, подборка работ по бюджету, оплата, напоминания о брошенных диалогах, MAX-бот.
