# Spec 005: Импорт каталога картин из xlsx

**Status**: Draft
**Created**: 2026-10-02
**Зависит от**: 004-artwork-multi-images (модель `Artwork`), поля карточки (размер/техника/год/статус) — новая миграция
**Генератор шаблона**: `scripts/catalog/build_catalog.py` (выгрузка с `/api/public/gallery`)

## Цель
Мама заполняет таблицу (Google Sheets → «Скачать → xlsx»), админ загружает файл в админке → предпросмотр изменений → применение. Импорт **никогда не падает целиком**: плохая строка = предупреждение/ошибка в отчёте, остальные применяются.

## Контракт файла (v1)

### Общие правила
- Формат: `.xlsx` (OOXML). `.xls`/`.csv` → отказ с понятным сообщением.
- Лист ищется **по имени** (`Каталог`, `Фото с выставок`), не по индексу. Нет листа `Каталог` → ошибка файла.
- Колонки ищутся **по заголовку в строке 1** (trim, регистр и `ё/е` не важны, `\s+` → пробел). Порядок колонок, лишние колонки — допустимы.
- Обязательные заголовки: `ID`, `Название`. Остальные опциональны: нет колонки → поле не трогаем.
- Формулы читаются как кэшированное значение; `=IMAGE(...)` игнорируется.
- Пустые строки (все EDIT-ячейки пусты) пропускаются молча.
- **Пустая ячейка = «не менять»**, не «очистить». Очистка — значение `-` (дефис).
- Лимит: 5 МБ, 2000 строк.

### Лист «Каталог»
| Заголовок | Поле | Тип / парсинг | Ошибка → |
|---|---|---|---|
| `ID` | ключ | int > 0, существующий `Artwork.Id`; пусто → **новая работа** | неизвестный ID → строка пропущена (error) |
| `Раздел на сайте` | — | справочно, игнор (смена категории в v1 не поддерживается) | — |
| `Название` | `Title` | string ≤ 200, trim | пусто у новой → error |
| `Цена, ₽` | `Price` | число; допускаются `150 000`, `150000 ₽`, `150 000,00`; `по запросу` → null | не число → warning, поле не трогаем |
| `Статус` | `Status` | enum из списка ниже, сравнение без регистра | неизвестное → warning |
| `Ширина, см` / `Высота, см` | `WidthCm` / `HeightCm` | decimal 1–1000, `,`→`.` | warning |
| `Год` | `Year` | int 1950–текущий; `2017г.`, `2017 год` → 2017 | warning |
| `Основа` | `Support` | string ≤ 100 | — |
| `Техника` | `Technique` | string ≤ 100 | — |
| `Короткое описание (1–2 предложения)` | `ShortDescription` | string ≤ 300 | > 300 → warning, обрезка не делается, поле не трогаем |
| `История, выставки, интересные факты` | `Description` | string ≤ 5000, переносы строк сохраняются | warning |
| `⭐ Сильная работа` | `IsFeatured` | `да`/`+`/`1`/`true` → true; `нет`/`-` → false | — |
| `Фото: переснять?` | `NeedsReshoot` (только админка) | непусто → true | — |
| `Комментарий` | — | показывается в отчёте предпросмотра, в БД не пишется | — |
| `Возможный дубль (ID)`, `Ссылка на сайте`, `Текущий текст на сайте` | — | справочно, игнор | — |

Статусы → enum `ArtworkStatus`:
`В наличии`→`Available`, `Продана`→`Sold`, `Частная коллекция`→`PrivateCollection`, `Недоступна`→`Unavailable`, `Не продаётся`→`NotForSale`, `Не моя работа`→`NotMine` (скрыть с сайта, не удалять).
Совместимость: `IsForSale` = `Status == Available` (вычисляется, старое поле не ломаем).

### Лист «Фото с выставок»
`ID` + `Оставить на сайте?` (`да`/`нет`) → `нет` = скрыть (не удалять). `Где и когда` → `Description` (если не пусто). Остальное игнор.

### Лист «О себе»
В v1 **не импортируется** — тексты переносит админ вручную в `/admin/pages` (существующий `PageContent`).

### Новые работы (пустой ID)
Создаются как черновик (`IsPublished=false`) без фото, в категории по умолчанию; в отчёте — «добавьте фото в админке». Дубль по точному названию с существующей → warning.

## Процесс импорта
1. `POST /api/admin/catalog/import?dryRun=true` (multipart) → отчёт: `{summary:{updated,created,skipped,warnings,errors}, rows:[{row, id, title, changes:[{field, old, new}], issues:[{level, column, message}]}]}`.
2. Админка показывает diff (только изменённые поля), фильтр «только с ошибками».
3. `POST ...?dryRun=false` с тем же файлом → применение **в одной транзакции** для валидных строк; строки с error пропускаются.
4. Перед применением — снимок изменяемых полей в `CatalogImportLog` (кто, когда, json old-values) → возможность отката последнего импорта.
5. Идемпотентность: повторный импорт того же файла → 0 изменений.

## Нефункциональные
- Парсер — `ClosedXML` (MIT) в `MomSite.Infrastructure/Catalog/`; маппинг заголовков и парсеры значений — чистые функции, покрыты unit-тестами (P5).
- Таблица фикстур: реальный выгруженный файл (обезличивать не нужно) + файл из Google Sheets (проверить, что экспорт Google не меняет заголовки/валидацию).
- Конституция P3: парсер колонок, валидатор, применитель — отдельные классы ≤ 200 строк.

## Не делаем в v1
Смена категории, загрузка фото из таблицы, импорт «О себе», двусторонняя синхронизация с Google Sheets API.

## Открытые вопросы
1. Порядок «ширина × высота» — мама подтверждает в таблице; на сайте показывать `Ш × В см`.
2. `ShortDescription` vs текущий `Description`: при пустом коротком — показывать первые 160 символов полного?
3. `NotMine` — скрывать или удалять? (по умолчанию скрываем)
4. Нужно ли версионировать шаблон (ячейка `Как заполнять!A20 = "format: v1"`)? Рекомендация: да, импорт проверяет и предупреждает при несовпадении.
